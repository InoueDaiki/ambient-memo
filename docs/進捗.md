## 仮で決めたこと

あとで変えてよい判断を残す。

- コードの PR のマージは自動判定で止められたので、利用者の確認を待つ。以降の作業は未マージのブランチの上に積む
- CI の動きを見るために、ブランチの push と PR の作成は確認なしで行う(利用者の指示)

- 画面の結合テストは Jest(jest-expo)で動かす。React Native を Vitest で読み込むのが難しいため。ほかの JS のテストは Vitest のまま
- `EngineClient` は変えず、聞き取りの操作は `TranscriptEngineClient` に分けた。`modules/engine-bridge` が実装したら `apps/mobile/src/engine.ts` で差し替える

- `first-goal` を PR 2 と PR 3 の統合ブランチにして、後続の作業をこの上に積む
- 画面のテストのタイムアウトを 30 秒に延ばした。CI の初回の読み込みが既定の 5 秒を超えたため
- `SpeakerEmbedder` はポートと Fake だけで、パイプラインからはまだ呼ばない
- スキーマ版 1 に話者の列は入れない。話者識別を作るときに足す
- `CaptureConfig` の既定値は仮(発話の上限 30 秒、待ちの上限 120 秒など)

- LLM は Gemma 4 E4B を LiteRT-LM の GPU で動かす構成を仮の第一候補にする。次善は E2B。検索は EmbeddingGemma 2 Text 270M
- LiteRT-LM の制約デコードは E4B で全件が空の出力だったので使わず、自由形式の JSON を解析する
- thinking は話者名の推定にだけ使う

## 調べること

- E4B には Tensor G6 向けの NPU ファイルがない。Pixel の GPU での速度、メモリ、発熱を測る

- 実行中にマイク権限を取り消すと、通知も欠落の記録もなく止まる
- OS に音声を無音化されたことを検知できない
- 実機で、実際の声が `AudioRecord` から届くことを確かめる
- `expo install --check` が TypeScript 7 に対して 6 系を推奨している
