## 仮で決めたこと

あとで変えてよい判断を残す。

- 完了した PR は、CI の成功を確かめて `main` にマージしてよい(利用者の指示)
- CI の動きを見るために、ブランチの push と PR の作成は確認なしで行う(利用者の指示)

- 画面の結合テストは Jest(jest-expo)で動かす。React Native を Vitest で読み込むのが難しいため。ほかの JS のテストは Vitest のまま
- `EngineClient` は変えず、聞き取りの操作は `TranscriptEngineClient` に分けた。`modules/engine-bridge` が実装したら `apps/mobile/src/engine.ts` で差し替える

- `first-goal` を PR 2 と PR 3 の統合ブランチにして、後続の作業をこの上に積む
- 画面のテストのタイムアウトを 30 秒に延ばした。CI の初回の読み込みが既定の 5 秒を超えたため
- `SpeakerEmbedder` はポートと Fake だけで、パイプラインからはまだ呼ばない
- スキーマ版 1 に話者の列は入れない。話者識別を作るときに足す
- `CaptureConfig` の既定値は仮(発話の上限 30 秒、待ちの上限 120 秒など)

- LLM は Gemma 4 E4B を LiteRT-LM の GPU で動かす構成を仮の第一候補にする。次善は E2B。検索は EmbeddingGemma 2 Text 270M
- LiteRT-LM の制約デコードは E4B で全件が空の出力だったので使わず、自由形式の JSON を解析する
- thinking は話者名の推定にだけ使う

- VAD は `silero_vad.onnx`(しきい値 0.5)、ASR は `sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01` の int8、話者は CAM++ advanced を仮の第一候補にする。ReazonSpeech の扱いは下の確認事項に残し、次点は `sensevoice-2024`
- 日本語のストリーミングは使わず、発話区間ごとに処理する。CER が第一候補のほぼ 2 倍だったため
- 区間の前後に実音声と無音を 0.3 秒ずつ足す。実音声の分はメモリのリングバッファに持つ
- 話者のしきい値はコサイン類似度 0.6 から始め、端末で自分の声に合わせて調整する
- `adapters` は JVM 用と Android 用に分け、同じ契約テストを流す。sherpa-onnx の jar と AAR の API が違うため

- ToDo の完了は `completed_at_ms` と `completed_from_status` を持つ。候補か確定かを失わないため。取り消しの画面はまだない
- 整理ジョブが動くまで、実機のメモ一覧は空のまま
- 話者は区間全体で 1 つの embedding にした。窓ずらしは誤受入が 4.4% に減るが、自分の再現率が 94.9% から 71.4% に落ちるので採らなかった
- 自分を登録する前は話者を判定せず、発話は「不明」にする
- 話者のしきい値は `selfThreshold`、`provisionalThreshold` とも 0.6。2.5 秒より短い区間は仮の話者を作らない
- 登録は 3 秒以上の区間を 3 つ使った単純平均。登録し直す画面と、手動で名前を変える画面はまだない

- モデルの取得は利用者の操作でだけ始め、Wi-Fi に限らない。通信が切れたら自動で再試行せず、「続きから取得する」を押す
- 通信先は https の `github.com` と `*.githubusercontent.com` に限る。INTERNET はモデルの確定まで Release にも残す
- 途中でやめた取得のファイルを消す操作はない。最大 700 MB ほどが次の取得まで残る

- 画面用の境界は `MemoEngineClient` に分けた。エンジンにつなぐとき、`TodoStatus` に `DONE` を足す
- ToDo の完了は取り消せない。取り消しを入れるなら、状態とは別に `completedAt` を持つ
- `integration-2` を PR 7 と PR 8 の統合ブランチにして、後続の作業をこの上に積む
- 区切りの無音は VAD 側で 0.8 秒にした。語の欠落と分割が減る代わりに、保存する時刻は開始が約 0.3 秒早く、終了が約 0.8 秒遅い
- 雑音の除去は仮の規則にした。文字と数字が 1 文字なら除き、2 文字は区間が 2 秒以上なら除く。短い相づちは保存されにくい
- ASR のスレッド数は 2。モデルは最初の発話で読み込み、停止まで保持する
- PR 8 はアプリに取得処理を持たず、Release の INTERNET も外していた。「モデルの確定までアプリが取得する」という方針と違い、スマホだけでは動かせないので、アプリ内の取得を足して INTERNET は確定まで残す

- 整理ジョブの既定値は仮(無音 5 分か 1,800 字で分割、再試行 1 回)。1,800 字が E4B の文脈長に収まるかは未確認
- 話者識別ができるまで、文字起こしは話者ラベルなしで LLM に渡す。検証はラベルつきで測ったので、適合率と再現率はそのまま当てはまらず、他人の作業が ToDo に混ざることがある
- 期限の確度は LLM に出させず、規則で判定する。手がかりがない日付や過去の日付は候補として扱う
- `due_date` は `YYYY-MM-DD` の文字列にする。時刻はミリ秒という規約の例外
- 録音できなかった時間も、メモの分割では無音として数える

## 調べること

- E4B には Tensor G6 向けの NPU ファイルがない。Pixel の GPU での速度、メモリ、発熱を測る
- sherpa-onnx の jar と AAR は版を固定した URL から取得するだけで、SHA-256 を照合していない。Gradle の依存検証を入れるか決める
- 最初の発話でのモデル読み込みの時間を測る
- 整理ジョブは、特定のまとまりで LLM の例外が続くと毎回そこで止まる。入力長の超過などの見分け方を、LiteRT-LM のアダプターで決める
- `PRAGMA foreign_keys` を有効にしていないので、SQLite は外部キーを強制しない。有効にするか決める
- 区切り 0.8 秒では、2 人以上が入る区間が clean で 25%、SNR 15 dB で 38% あり、他人を「自分」と誤る率が約 30% になる(合成会話の時間ベース)
- `[HH:mm] 本文` と `自分:` が混ざる文字起こしでの LLM の品質を測る
- SNR 15 dB で話者の DER が 44.6% に悪化した。雑音の中の短い区間の扱いを決める
- zipformer は VAD の誤検知区間のすべてで文字を出した(平均 1.8 文字)。DB に書く前に除く方法を測る
- 実際の会話での CER を測る。JVS は読み上げなので数値はよく出る
- Pixel で sherpa-onnx の AAR を動かし、速度、メモリ、スレッド数を測る

- 実行中にマイク権限を取り消すと、通知も欠落の記録もなく止まる
- OS に音声を無音化されたことを検知できない
- 実機で、実際の声が `AudioRecord` から届くことを確かめる
- `expo install --check` が TypeScript 7 に対して 6 系を推奨している

## 確認してほしいこと

- ASR の第一候補は ReazonSpeech で学習している。モデルは Apache-2.0 だが、データセットには著作権法第 30 条の 4 の目的に限る条件があり、学習済みモデルの扱いは書かれていない。使い続けるか、`sensevoice-2024` に替えるか決める(詳細は [検証-ASR.md](検証-ASR.md))
- 聞き取り中の通知はサイレント欄に入り、「停止」には展開が要る。重要度を上げるか決める
- 手動で止めていても、再起動のたびに通知が出る。止めていたときは出さないか決める

- 署名鍵を作り、GitHub Secrets に4つの値を設定する(手順は骨組みの README の「署名鍵」)。これがないと Release APK はビルドできない
- アプリ ID `dev.ambientmemo.app` は仮の名前。配布後は変えられないので、最初のタグの前に確認する
