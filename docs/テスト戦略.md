# テスト戦略

結合テストを中心にしたテスティングトロフィーに、通常のテストでは測れない品質評価と実機指標を足す。

## テストの層

| 層 | 対象 | 手段 | 実行場所 |
|---|---|---|---|
| 実機指標 | 電池、発熱、遅延 | Pixel で計測 | 手元 |
| 品質評価 | ASR、話者識別、話題の切れ目、質問の答え | 公開データと固定の会話セット | 手元 |
| E2E | 主要な利用の流れ | エミュレーターに WAV を入力 | タグ、手動 |
| 結合(主役) | ロジックをつないだ流れ | 下記 | PR |
| 単体 | 判定や解析などの純粋な処理 | JUnit、Vitest | PR |
| 静的解析 | 型、規約、依存の向き | コンパイラ、detekt、oxlint | PR |

## 結合テスト

- エンジン: `domain` に本物の SQLite と Fake の ASR、LLM をつなぎ、WAV 入力から DB 保存、メモの整理、質問までを通す
- 画面: Fake の `engine-client` を差し込み、React Native Testing Library で操作を確かめる
- Fake の信頼性: 同じ契約テストを Fake と本物の実装の両方に流す
- DB マイグレーション: 全バージョンからの移行を確かめる。音声を残さないので、壊すとメモを復元できない

- モデルの取得: `ModelDownloaderTest` が本物の HTTP の実装を、テスト内のローカルのサーバーへつなぐ。ハッシュの不一致、途中の切断、再開、容量不足、キャンセルを確かめる

マイク入力はインターフェースにして、WAV ファイルに差し替えられるようにする。

## 本物のモデルのテスト

モデルはコミットしない。`mise run models:fetch` で `engine/.cache/models` に取得する。

- JVM: `mise run test` が契約テストと、WAV から SQLite までの結合テストを本物のモデルで流す。モデルがなければ飛ばす。CI は `AMBIENT_MEMO_REQUIRE_MODELS=true` で飛ばさず失敗させる
- 端末: AAR の実装には、起動中のエミュレーターか実機で次を実行する。モデルがなければ失敗する

```bash
engine/gradlew -p engine :adapters-sherpa-android-test:installDebugAndroidTest
ANDROID_SERIAL=<端末> scripts/push-models.sh dev.ambientmemo.engine.sherpa.android.test.test
adb shell am instrument -w dev.ambientmemo.engine.sherpa.android.test.test/androidx.test.runner.AndroidJUnitRunner
```

- LLM: `adapters-llm-android-test` が本物のモデルを端末で動かす。CI では流さない(3.66 GB あり、ランナーの Android で動かす環境がない)。OpenCL のないエミュレーターでは CPU で動く

```bash
engine/gradlew -p engine :adapters-llm-android-test:installDebugAndroidTest
ANDROID_SERIAL=<端末> scripts/push-llm-model.sh <gemma-4-E4B-it.litertlm のパス> dev.ambientmemo.engine.llm.android.test.test
adb shell am instrument -w dev.ambientmemo.engine.llm.android.test.test/androidx.test.runner.AndroidJUnitRunner
```

- 画面まで: Debug ビルドの内部ストレージに `debug-input.wav` を置いて聞き取りを始めると、エミュレーターでも本物のモデルを通して一覧に出る。声の登録も同じファイルを読む。モデルは `models:push` でも、画面の「モデルを取得する」でも入れられる
- 話者: 結合テストは、固定のベクトルと本物の SQLite で通すものと、モデルの配布物の `test_wavs` で本物のモデルを通すものがある。`test_wavs` は話者が別なので、自分と他人の判定を確かめられる。JVS は再配布できないのでテストには使わない

## Release で本物のモデルを通す

Release は R8 を通るので、Debug で動いても動くとは限らない。sherpa-onnx と LiteRT-LM のネイティブはクラスを名前で探し、R8 に消されると例外にならずプロセスごと落ちる。ネイティブのライブラリ、R8 の設定、JNI を使う依存関係を変えたら、次を確かめる。

- 静的な検査: `mise run build:android:release` の中で `scripts/check-release-native-classes.sh` が、AAR のクラス、フィールド、ネイティブメソッドが同じ名前で dex に残っていることを確かめる。PR では CI の「Release の検査」が使い捨ての鍵で同じビルドを流す
- 端末での確認: 手元で署名した Release を arm64 のエミュレーターか実機に入れて、次を画面から確かめる。Release は `run-as` が使えないので `models:push` は使えず、モデルは画面の「モデルを取得する」と「整理のモデルを取得する」で入れる。`debug-input.wav` も読まない

| 確認 | 期待 |
|---|---|
| 声の登録(無音) | 落ちない。1 分以内に「声を十分に聞き取れませんでした」が出る |
| 声の登録(発話あり) | 登録の案内が消える。話者のモデルはここで初めて読み込まれる |
| 聞き取りの開始と停止 | 状態が切り替わる。発話があれば文字起こしが一覧に出る。ASR のモデルは発話が来てから読み込まれる |
| 整理 | `:organize` のプロセスでモデルを読み込み、`AmbientMemoOrganize` のログに結果が出て、メモの画面に並ぶ |
| 今すぐ整理する | `adb shell dumpsys battery unplug` の状態で完走する。`:organize` に dataSync の Foreground Service が付き、通知に進行と「止める」が出る |

どの確認でも `adb logcat -b crash` にアプリのクラッシュが出ないことを見る。

無音では VAD しか読み込まれないので、エミュレーターでは発話を流す。エミュレーターを `-grpc <ポート>` で起動し、SDK の `emulator/lib/emulator_controller.proto` の `injectAudio` で 16 kHz、モノラル、16 bit の PCM を送ると、アプリのマイクに届く。音声はモデルの配布物の `test_wavs` を使う。

整理は充電中で端末を使っていないときに動き、最後の発話から 5 分たつまでは対象にならない。実行の間隔は 6 時間ある。エミュレーターでは時計を進めてから、条件を無視して実行する。`<番号>` は `adb shell dumpsys jobscheduler` の `OrganizeWorker` の `JOB` の行にあり、実行のたびに変わる。

```bash
adb shell settings put global auto_time 0
adb shell cmd alarm set-time <7 時間後のエポックミリ秒>
adb shell cmd jobscheduler run -f -n androidx.work.systemjobscheduler dev.ambientmemo.app.dev <番号>
adb logcat -s AmbientMemoOrganize
```

CI では本物のモデルを Release に通さない。ランナーで動くエミュレーターは x86_64 で、配布する arm64 の APK は動かない。x86_64 でビルドし直して、エミュレーターの起動と 743 MB の取得を毎回行うことになり、PR の CI の目標に収まらない。Release のビルドを変える PR では手元で確かめる。

## 目標

カバレッジの全体値ではなく、速さ、安定性、壊れやすい箇所の保証を基準にする。数値は仮。

| 指標 | 目標 |
|---|---|
| 手元の単体テストと結合テスト | 30 秒以内 |
| PR の CI(Android ビルドなし) | 5 分以内 |
| フレーキーテスト | 0 件。原因を直さずにリトライで通さない |
| E2E | 5 本以内 |
| `domain` のカバレッジ | 90% 以上 |
| DB マイグレーション | 全バージョンを網羅 |

## 品質と実機の目標

ASR などは、最初の測定をベースラインにして、悪化を検知する。

| 対象 | 指標 | 目標(仮) |
|---|---|---|
| 文字起こし | 文字誤り率(CER) | ベースラインから悪化させない |
| 発話検知 | 取りこぼし率、1時間あたりの誤検知 | 同上 |
| 話者識別 | 話者誤り率(DER)。合成データなので参考値 | 同上 |
| 質問の答え | 根拠のメモの適合率と再現率、答えの正しさ | データセットは未作成 |
| 電池 | 1日の消費 | 20% 以内 |
| 遅延 | 発話の終了から保存まで | p95 で 5 秒以内 |

LLM の評価用データは、架空の会話を作って正解を付ける。個人の会話ではないのでコミットしてよい。作るときにクラウドの LLM を使ってもよい。

## 実機の確認項目

- プロセスの強制終了
- マイク権限の取り消し
- 通話や他アプリによるマイクの占有
- メモリ不足での LLM の停止
- 整理の途中での充電終了
- 再起動後の通知から記録を再開する流れ
